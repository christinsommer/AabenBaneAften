# Local development

## Prerequisites and setup

Use Node.js 22.13 or later, npm, and Windows PowerShell for the supplied launcher. .NET 10 SDK is required for optimizer builds and full checks. Docker Desktop with Linux containers is needed for container deployment, not ordinary UI development.

Run from the repository root:

```powershell
npm.cmd ci
# Only when .dev.vars does not exist:
Copy-Item .dev.vars.example .dev.vars
node scripts/setup-mfa.mjs --local
npm.cmd run dev
```

The `.cmd` launchers avoid PowerShell policy errors from npm/npx `.ps1` wrappers.

`predev` frees port 3000, applies local migrations, and starts Next.js on `localhost:3000`. The port script can stop the listening process and its descendants, plus stale Next.js processes for this project. Check for unrelated use of that port first. Startup fails instead of switching to port 3001.

The active local database is under `.wrangler/local-dev/v3`. Initial setup can back up/import a legacy `.data/app.db`; that file is not the active database afterwards. Existing D1 data is preserved, with backup and rehearsal before pending migrations.

New databases have no production members or administrator. Public registration creates a player. See [administrator provisioning](../SUPERADMIN.md).

## Local settings

Use `.dev.vars.example` as a template, keep real values in ignored `.dev.vars`, and restart the app after changes.

| Setting | Purpose |
| --- | --- |
| `MFA_ENCRYPTION_KEY` | Local MFA encryption key; generated by the setup script |
| `SUPERADMIN_PLAYER_ID` | Verified internal player ID, not a membership number |
| `OPTIMIZER_URL` | Usually `http://127.0.0.1:5117` for the standalone local solver |
| `OPTIMIZER_API_KEY` | Matching app/solver secret, at least 32 characters |
| `RESEND_API_KEY` | Enables real mail; leave absent when local work must not send |
| `NEWSLETTER_ENABLED` | Newsletter gate; keep `false` in tests |

Disabling newsletters does not disable transactional email. A database copy does not copy these settings. Do not point a local experiment at production services unintentionally.

## Optimizer development

```powershell
npm.cmd run optimizer:test
npm.cmd run optimizer:start
```

Keep the solver running in a second terminal. The start script creates missing local key/URL settings but preserves existing values; check that an existing URL points locally.

The standalone solver supports direct and synchronous API tests. The main calculation button uses durable jobs and additionally needs the optimizer Worker, shared local persistence, and scheduled-event dispatch. Next.js alone does not run cron. See [optimizer setup](../optimizer-service/README.md) and [background jobs](optimizer-background-jobs.md).

## Verification

| Command | Scope and side effects |
| --- | --- |
| `npx.cmd tsc --noEmit` | Types; can update incremental metadata |
| `npx.cmd eslint path/to/file.ts` | Focused lint |
| `npm.cmd run lint` | Whole-repository lint; distinguish existing failures |
| `node --test tests/spouse.test.mjs tests/optimizer.test.mjs tests/plan-review.test.mjs` | Rule/scoring tests |
| `npm.cmd run optimizer:test` | Restore, build, and real solver tests |
| `npm.cmd run cf:build` | Cloudflare artifact build |
| `npm.cmd test` | Solver tests, Cloudflare build, then Node tests |
| `npm.cmd run test:d1` | Solver and Node tests; no Cloudflare build first |
| `npm.cmd run release:check` | Full local build and serialized release tests; no production commands |

Some integration tests require the Cloudflare artifact and solver binary. Inspect their setup before running them individually. Stop development before builds to avoid `.next` and `.open-next` locks. `release:check` writes `lib/release-info.json`; it is not filesystem read-only.

Use synthetic accounts or isolated fixtures for browser checks. `scripts/check-plan-editor.mjs` exercises a fake-data page in Windows Edge without production/database access.

For login presentation changes, follow the [login design verification checklist](login-design.md#verification). Mock `/api/**` before navigation to avoid database activity and real reset/registration emails. Check narrow mobile and desktop layouts, registration, PIN recovery, MFA, and legal links. A viewport test is not a test on a physical iPhone.

Regenerate approved app icon sizes with `node scripts/generate-app-icons.mjs`; it reads the committed source in `public/brand/`, not a machine-specific design file. Do not replace the approved artwork with generated alternatives.

## Troubleshooting

| Symptom | Next check |
| --- | --- |
| PowerShell blocks npm | Use `npm.cmd` / `npx.cmd` |
| Port or build directory locked | Inspect its owner and stop the relevant local process |
| No expected members | Confirm D1 persistence path, not the old `.data/app.db` |
| MFA fails after copying | [Copied MFA state](admin-2fa.md#production-data-copied-to-sandbox) |
| Job stays queued | Worker/cron dispatcher and shared local D1 |
| Mail fails | [Email configuration and delivery](email-delivery.md) |
| Release lock remains | Check for an active release before removing a stale lock |

Do not delete local data or reset configuration as a generic fix. Diagnose the target and preserve a backup when replacing data.
